## 项目定位

Interview Agent 是一个面向程序员的 AI 持续迭代面试训练系统。

系统通过 AI 模拟面试、动态追问、答案评估、能力分析、薄弱点识别以及真实面试反馈，帮助用户形成：

**学习 → 模拟面试 → 发现问题 → 针对性学习 → 再次模拟 → 真实面试 → 面试复盘 → 反哺训练**

的持续迭代闭环。

第一阶段主要服务于项目创建者本人，用于准备：

- Java 后端开发岗位
- AI 应用开发岗位
- 大模型应用开发岗位
- Agent 开发岗位

后续根据实际使用效果，再扩展到其他程序员及其他职业。

---

## 项目背景

传统面试准备主要依赖刷题、背面试题和查看标准答案，存在以下问题：

1. 面试题与个人实际水平不一定匹配。
2. 用户知道“答案是什么”，但不一定真正理解。
3. 缺少接近真实面试场景的连续追问。
4. 很难客观评价自己的回答质量。
5. 面试结束后缺少系统性的能力分析。
6. 多次模拟面试产生的数据没有形成长期能力画像。
7. 真实面试中暴露的问题通常是一次性的，难以沉淀并用于下一次训练。

因此，本项目希望利用大模型的理解、推理、追问和评估能力，将面试准备从“静态刷题”升级为“持续训练”。

## 第一阶段目标岗位

系统第一阶段支持以下岗位：

- Java 后端开发

- 大模型应用开发


- 完整面试复盘

## 面试模式

第一阶段支持两种面试模式。

### 完全面试

由 AI 面试官自主决定面试流程。

基本流程：

```text
开始面试
    ↓
AI 根据岗位、经验、历史表现选择问题
    ↓
用户回答
    ↓
AI 分析回答
    ↓
AI 判断是否需要追问
    ↓
追问 / 进入下一题
    ↓
继续面试
    ↓
结束面试
    ↓
查看完整面试复盘
```

该模式主要用于模拟真实面试。

### 指定方向面试

用户指定本次重点考察的技术方向。

例如 Java 后端：

```text
Java
Spring
MySQL
Redis
RabbitMQ
JVM
分布式
微服务
系统设计
```

例如 AI 应用开发：

```text
LLM
Prompt Engineering
RAG
Agent
ReAct
Tool Calling
MCP
Memory
Multi-Agent
Evaluation
```

AI 在用户指定范围内生成问题并进行追问。

两种模式均属于 MVP 范围。

## AI 评分维度

系统不只判断回答“正确 / 错误”，而是从多个维度评价用户回答。

### 知识准确性

判断回答中的技术知识是否正确，是否存在明显错误或概念混淆。

### 完整性

判断回答是否覆盖问题要求的关键知识点。

### 深度

判断用户是否能够从原理、底层机制、实现细节、设计思想等方面进行深入回答。

### 表达能力

评价回答是否清晰、简洁、易于理解，以及是否能够有效表达技术观点。

### 逻辑性

评价回答是否结构清晰、层次合理，是否能够形成完整的因果关系。

### 项目经验

对于与实际项目相关的问题，评价用户是否能够结合真实项目说明问题，以及是否体现实际工程经验。

### 应变能力

结合连续追问评价用户面对未知问题、变化问题和深入追问时的分析及应对能力。

## 核心业务闭环

Interview Agent 的核心不是一次性模拟面试，而是持续迭代。

```text
知识准备
    ↓
AI 模拟面试
    ↓
用户回答
    ↓
AI 评估
    ↓
AI 追问
    ↓
面试结束
    ↓
查看完整面试复盘
    ↓
识别薄弱知识点
    ↓
针对性学习
    ↓
再次模拟面试
    ↓
能力提升
    ↓
真实面试
    ↓
真实面试复盘
    ↓
将真实面试问题及反馈加入系统
    ↓
更新训练重点
    ↓
再次训练
```

该闭环是本项目最核心的产品价值。

## MVP 核心功能范围

第一阶段 MVP 至少包含以下能力。

### 创建面试

用户可以选择：

- 面试岗位
- 面试模式
- 技术方向
- 面试难度
- 面试时长或题目数量（具体规则在需求阶段确定）

### AI 面试官

AI 根据当前岗位及面试模式进行提问。

### 用户回答

用户通过文本回答问题。

### 动态追问

AI 根据用户当前回答决定：

- 是否继续追问
- 追问什么
- 是否进入下一题

### 答案评估

AI 对用户回答进行多维度评分。

### 完整面试复盘

面试结束后基于已持久化业务事实查看：

- 面试开始、完成与实际持续时间
- MAIN / FOLLOW_UP 数量及回答状态统计
- MAIN + FOLLOW_UP 完整问题链
- 用户回答
- 逐题评分、优势、问题、遗漏点和参考答案
- 适用维度的评分与解释

V0.1 不额外生成 Interview-level AI 总结或综合报告。

### 面试历史

保存历史面试记录，以支持后续分析和能力变化跟踪。

## 核心产品指标

项目计划建立一个核心指标：

> **Interview Readiness Score（面试准备度）**

用于反映用户当前针对某一岗位的整体面试准备程度。

例如：

```text
Java 后端开发

Java 基础       82
Spring          78
MySQL           75
Redis           81
MQ              68
JVM             80
分布式          72
系统设计        65
项目经验        88
表达能力        76

综合面试准备度  76
```

该指标不应简单等于一次面试评分，而应结合多次模拟面试结果逐步形成。

后续可以支持：

```text
第 1 次：67
第 5 次：71
第 10 次：76
第 20 次：82
```

从而观察用户能力变化趋势。

## MVP 成功标准

MVP 的核心验收标准为：

> **用户可以选择 Java 后端或 AI 相关岗位，完成一次约 30～45 分钟的 AI 模拟面试；AI 能够根据用户回答进行合理追问、从多个维度评价回答，并在面试结束后生成详细的能力分析和改进建议。**

同时应满足：

1. 面试过程能够完整闭环。
2. AI 能够根据回答进行动态追问，而不是简单按照固定题库顺序提问。
3. AI 评分具有明确的评分维度和评分依据。
4. 面试结束后能够识别用户的主要薄弱点。
5. 历史面试能够保存。
6. 用户能够通过多次面试观察自己的能力变化。
7. 系统具备实际可用性，而不是仅用于技术 Demo。

## 产品核心价值

Interview Agent 最终希望解决的不是：

> “帮用户做一道面试题。”

而是：

> **“帮助用户持续提升通过目标岗位面试的概率。”**

因此系统应该逐渐从：

```text
AI 出题工具
```

演进为：

```text
AI 面试官
    ↓
AI 面试教练
    ↓
个人能力分析系统
    ↓
持续面试训练系统
```

## Phase 0 验收结论

Phase 0 已确定：

- **目标用户**：第一阶段为项目创建者本人
- **目标岗位**：Java 后端、AI 应用、大模型应用、Agent 开发
- **岗位选择**：创建面试时明确选择目标岗位
- **面试模式**：支持完全面试和指定方向面试
- **回答方式**：MVP 仅支持文本
- **评分方式**：支持知识准确性、完整性、深度、表达能力、逻辑性、项目经验、应变能力等多维度评价
- **核心产品闭环**：模拟面试 → 评估 → 发现问题 → 针对性训练 → 再次面试 → 真实面试 → 反馈 → 持续迭代
- **MVP 成功标准**：能够完成一次 30～45 分钟、支持动态追问和多维评价的完整 AI 模拟面试，并生成能力分析和改进建议。
